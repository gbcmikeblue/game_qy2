> 适用项目：`Iso RPG Stage A`（64×32 逻辑菱形等距、GDScript、GL Compatibility）
> 用途：阶段 E「美术、音频和打磨」前的技术选型与资产管线参考

## 1. 风格前提（先纠正一个关键定性）

本项目**不是像素风**。设计文档 6.1 的目标是「**复古、细节丰富、易读的 2D 等距幻想世界**」，并明确要求统一「等距投影角度、光照方向、阴影硬度、色彩饱和度、描边与材质风格、对比度」，同时警告「不要从多个素材包随意拼接，容易出现视角、透视、光源和**像素密度**不一致」。

也就是说：风格是**复古气质的高清手绘/数码绘制 2D**（detail-rich 2D isometric），而不是低分辨率像素网格。这个定性会连带改变四件事：

| 影响面 | 像素风的做法 | 本项目应采用的做法 |
|---|---|---|
| 动画生产方式 | 逐帧精灵表（帧少、单帧成本低） | **骨骼/网格变形为主**（单帧细节成本高，逐帧画不划算），帧动画只用于特效与简单循环 |
| 纹理过滤 | `nearest`，整数倍缩放 | **`linear` + mipmap**（手绘贴图非整数倍缩放时 nearest 会出锯齿与采样错位） |
| 资产分辨率 | 1 格 = 64×32 直接绘制 | 逻辑格仍是 64×32，但**按 2×–4× 绘制再缩小**（超采样）保留细节 |
| 换装 | 整图重绘或调色板替换 | **分槽/分层**（Spine attachment slot 或 Sprite2D 多层），骨骼方案天然支持 |

### 1.1 必须同步修正的工程设置

`project.godot` 当前为：

```ini
[rendering]
textures/canvas_textures/default_texture_filter=0   # 0 = Nearest
```

`0` 是占位绘制阶段（全部 `_draw()` 矢量图形）留下的设置。**接入正式手绘美术时应改为 `3`（Linear with Mipmaps）**——至少要 `1`（Linear），但只有带 mipmap 的档位才能在缩小显示时避免摩尔纹与闪烁；同时在纹理导入面板开启 mipmap（`Mipmaps → Generate`）。否则在 `stretch/mode="canvas_items"` + `aspect="expand"` 的非整数倍缩放、以及 `Camera2D` 平滑移动时会出现锯齿、闪烁与纹理采样错位。UI 图标若希望保持锐利，可对单个 `TextureRect` 单独设 `texture_filter`，不要靠全局 nearest。

### 1.2 三条硬约束（与美术风格无关，来自现有代码）

1. **原点在脚底**：`PropNode` 与角色节点的 `position` 都是「占地范围最下方顶点」，父级 `Entities` 靠 `y_sort_enabled` 排序。新资源若把原点放中心，遮挡关系立即错乱。
2. **方向数**：物理上是自由 360° 朝向（`_turn_towards` 平滑插值），美术上只需 **4 或 8 个可分辨朝向**；`Iso.TILE_W/H = 64/32`（2:1 菱形）决定朝向按 NE/NW/SE/SW 设计。
3. **尺寸基准**：单格 64×32；角色屏幕高度建议 64–96 px（非像素风可比像素风更高），与 `PropNode` 的树（约 90 px）、建筑（52 px + 4/格）同处一个量级。

## 2. 三条技术路线（按本项目重新排序）

| 路线 | 做法 | 优点 | 代价 | 适配度 |
|---|---|---|---|---|
| **B. 2D 骨骼/网格变形** | Spine / DragonBones / Godot `Skeleton2D`+`Polygon2D` 权重 / Inochi2D | 一套骨架复用全部动作；分槽换装天然成立；单帧细节只画一次；动作可参数化混合 | 工具链与运行时成本；手绘素材需先切件（分层贴图 + 网格） | **首选**（阶段 E 主线） |
| C. 3D 建模 → 渲染/贴图 | Blender/Blockbench blockout → 手绘 overpaint 或固定等距相机渲染 | 等距透视天然正确；多角度免费；建筑/道具一致性最好 | 低模/体素观感与「细节丰富的手绘」有落差，需二次手绘 | **中高**（建筑、道具、地面结构） |
| A. 纯帧动画 | 逐帧精灵表 + `AnimatedSprite2D`/`SpriteFrames` | 实现最简；与现有 `set_facing` 一一对应；适合特效/UI/简单循环 | 4/8 向 × 6 动作的绘制量随细节度线性爆炸；换装需整图重绘 | **中**（特效、怪物变体、简单循环如篝火/旗帜） |

**结论**：**B 打底，C 补场景，A 收特效**。骨骼不是为了省事，而是非像素风下唯一能承受「4 向 × 6 动作 × 多套装备」成本的方案。

3. 预算为零 → **DragonBones 格式 + 第三方 Godot 导入器**，或 **Blender + Godot-2d-Bridge**（注意其无许可证，仅限内部验证）。

## 5. 推荐管线

### 管线 1：角色（骨骼为主）

```text
Krita 分层绘制（body / hair / armor / weapon 各一组，统一画布与脚底基准）
  → 导出分层 PNG（2× 绘制，游戏内缩到 1×）
  → Spine（付费）或 Blender→Skeleton2D 桥（免费但受许可）绑骨 + 刷权重
  → 动作：idle / walk / attack / cast / hurt / death（4 向）
  → 攻击动作打「事件标记」在命中帧（对应 ATTACK_WINDUP=0.22）
  → Godot：适配层保留 set_facing/set_health/flash/set_dead 方法签名
```

### 管线 2：等距地砖与地面材质

```text
Material Maker 节点图出可平铺底图（草地/泥地/石板/沙地/水面）
  → Krita overpaint 加手绘细节与统一描边/光照方向
  → 按 2:1 菱形（128×64 绘制 → 64×32 显示）切块
  → TileCropper 切分 → TileMapLayer（Isometric）
  → Laigter 批量出法线 → PointLight2D / CanvasModulate 做昼夜
```

### 管线 3：建筑与道具

```text
Blockbench 体块 blockout（1 格 = 64×32 底面，高度按 4px/级）
  → 正交等距相机截图作为透视参考
  → Krita 手绘 overpaint 成最终贴图（不用低模直接出图）
  → 替换 PropNode._draw_*()，碰撞体继续用现有 CollisionPolygon2D
```

### 管线 4：AI 辅助（只到「参考」为止）

```text
ComfyUI（ControlNet 约束等距视角 + 风格参考图）
  → 输出高分辨率候选
  → Krita 手绘重制（描边、结构、光照统一）
  → 不得直接进发行包
```

| `set_facing(Vector2)` | 存单位向量给 `_draw` | 骨骼方案下可改为「方向参数」直接喂给骨骼混合（如 Spine 的 4 向混合）；帧动画方案下量化为索引：`index = int(round(angle/45)) % 8`，4 向资产先偏 90° 再量化 |
| 纹理过滤 | `default_texture_filter=0`（nearest） | 改 `3`（linear + mipmap）并开纹理 mipmap，见 1.1；这是换成手绘美术的**前置条件**，不改会全程锯齿 |
| `PropNode._draw_*()` | 程序化画树/石/建筑/墙 | 换 `Sprite2D` 时**原点仍必须在脚底**（现为 `Iso.grid_to_world(cell + footprint - ONE) + (0, TILE_H/2)`），否则 `y_sort` 失效；`body_height` 由贴图高度取代 |
| `GroundRenderer` | 逐菱形 `draw_colored_polygon` | 换 `TileMapLayer`（Isometric）时图块锚点必须与 `Iso.grid_to_world()` 对齐，否则所有实体整体错位；建议先只替换渲染、逻辑仍走 `Iso` |
| `EnemyVisual.configure(def)` | 用 JSON 的 `color` 画色块 | 改按 `def.get("sprite", id)` 加载；`body_radius` 继续驱动碰撞圆 |
| 换装 | 无 | 骨骼 attachment slot 或 Sprite2D 多层（`z_index` 递增）；换装后需重算 `defense/attack`，与 `DataRegistry` 的装备表联动 |
| 性能 | `_draw` 成本极低 | 骨骼方案注意 draw call 与网格顶点数；同屏 12 个敌人时建议共享 `SkeletonData`、复用 `SpriteFrames` 资源，禁止逐实例复制纹理 |

1. **改渲染设置**：`default_texture_filter` → `3`（linear + mipmap），纹理开 mipmap；否则后面所有美术评估都失真。
2. **跑官方 `2d/skeleton`**（半天）+ **Krita 画 1 个 4 向待机角色分件**，评估原生骨骼的变形质量。

## 9. 一句话结论

- 本项目是**复古气质的高清手绘 2D 等距**，不是像素风：因此**骨骼/网格变形（Spine 优先）是主线**，帧动画只收特效，3D 只做 blockout 与透视参考。
- 换成任何手绘资产前，**必须先把 `texture_filter` 从 nearest 改为 linear 并开 mipmap**，否则锯齿和采样错位会让评估结论完全跑偏。
- 贴图管线最稳的组合是 **Krita（主绘制）+ Material Maker（材质底图）+ TileCropper（等距切分）+ Laigter（法线）**；像素专用工具（LPC 生成器、pixel-spark、Pixel-Perfect-Aligner、LibreSprite）与本项目风格不符，仅在需要 16×16 物品图标时局部参考。
